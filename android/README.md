# Android 客户端

Kotlin / Jetpack Compose 原生客户端，与 CLI 共用 `core/` 中的传输和会话实现。
采用 Material 3 原生界面，支持 TCP / UDP 映射、运行中重配、配置导入导出、房间语音和结构化连接报告。

底部导航悬浮在滚动内容之上，直接切换首页、服务、连接、语音和设置；选中透镜可拖动，松手按速度切页，取消拖动时回到原位置。启停按钮只在首页出现，切页时收起、返回时展开，导航同步调整宽度。首页使用醒目的状态区区分未连接、信令连接中、加入房间、已连接与异常，连接时显示进度环，成功时绘制勾选，并显示会话与流量。已连接表示已加入房间，服务通道是否可用另行说明。服务页以分享节点、终端窗口图标区分提供和使用服务；删除后的撤销提示位于悬浮导航栏上方，默认约 4 秒后消失，可左右滑动或点击关闭，切页时保留当前提示。无障碍设置可延长显示时间。连接页按设备或服务搜索、筛选，点选条目查看线路参数，右上角菜单打开网络诊断与报告。编辑页的保存、删除使用独立悬浮图标，不占用整条底栏。说明图标点击后弹出注释，输入错误直接显示在字段下方。

导航动效按 FlClash 的连续弹簧模型实现：透镜随速度拉伸、按压膨胀、局部放大染色、边缘橡皮筋和松手惯性；不依赖背景模糊。一级页面使用淡入缩放，编辑页面使用方向过渡；按钮按压、启停变形、分段选择、数值更新和列表增删均有动画，并遵循系统时长设置。分段选择等宽铺满；小屏或大字号超出宽度时可横向滚动。浅色、深色和跟随系统模式均可使用，另有五种强调色及 Android 12+ 动态配色。选择强调色会关闭动态配色并立即保存；重新开启后使用系统壁纸颜色。

Material 3 固定为 `1.5.0-alpha29`，以使用公开的 Expressive API。旧版外观配置字段仍可读取和写回，以兼容现有配置文件。

## 模块

| 模块 | 内容 |
| --- | --- |
| `app` | 手机界面、配置仓库、通知和前台服务 |
| [wear](wear/README.md) | 共用手机源码的 Wear OS 安装包，独立设备声明和 ABI 选择 |
| `corebridge` | Go AAR 构建、Kotlin 接口、Android Network / DNS / socket 适配 |

当前手机版本为 **0.3.7 / versionCode 9**，包名 `dev.hole.app`，仅打包 `arm64-v8a`。
最低 Android 8.0（API 26），compileSdk 37，targetSdk 36；版本以 [app/build.gradle.kts](app/build.gradle.kts) 为准。

## 构建

从仓库根目录执行：

```bash
cp -n signing.env.example signing.env
# 填写现有密钥库及对应密码、别名
./build.sh android
```

Gradle 自动调用 `:corebridge:bindGoCore`，从当前 Go 源码生成 `corebridge/libs/holecore.aar`。
共享 AAR 包含 ARM32 / ARM64，手机 APK 只选择 ARM64，不需要手工替换 AAR。

交付文件在仓库根目录 `dist/android/`：

- `hole-<version>-release.apk`
- `hole-<version>-release-mapping.txt`
- `build-manifest.json`、`SHA256SUMS`

Release 开启 R8 混淆、资源收缩与 native strip，保留 JNI 所需类和方法。
工具版本、签名配置和完整检查命令见 [构建指南](../docs/BUILDING.md)。

## 使用

1. 在“设置 → 房间与身份”填写服务器、凭据、房间和设备名。
2. 在“服务”添加提供或使用服务，与另一端使用相同服务 ID。
3. 启用条目，点击首页悬浮播放按钮，在“连接”查看线路及本地访问端口；返回首页点击暂停图标停止转发。
4. 在“语音”启用房间通话、查看成员或切换静音。
5. 在“设置 → 连接方式”选择自动、仅 ICE 或仅 IPv6，调整 STUN / TURN 设置，并排序或跳过中继类型。

房间语音使用 48 kHz 单声道 PCM16，每 20 ms 连续采集一帧，短读取累积到完整帧后提交。
共享核心以统一播放时钟混音各远端，每周期输出一帧；短时丢包使用 Opus PLC，长时间停流后重新缓冲，
多人重叠超过 PCM16 范围时对整帧限幅。本机成员单独标识；线路连通、媒体收发、麦克风采集是独立状态，
页面显示采集、混音、播放与各线路解码 / 补帧计数。播放计数表示 `AudioTrack.write` 已接受完整帧，
不证明扬声器实际发声。

通话期间采用 `MODE_IN_COMMUNICATION`，Android 12+ 优先通信耳机，未连接耳机时选择扬声器，
随设备插拔更新路由；较旧系统保留有线耳机及已有 Bluetooth SCO，其他情况使用扬声器。
可用时显式启用平台回声消除和降噪，页面显示实际启用结果。停止或初始化失败时释放音频资源、
恢复通话模式和路由；普通运行中配置保存不重复启动音频设备。厂商音效和真实听感仍需设备验收。

CLI YAML 可导入导出；应用完整备份还包含停用条目与界面设置。凭据由 Android Keystore
管理的 AES-GCM 密钥保护，默认导出不含凭据，备份不复制设备绑定的 Keystore 密文。

## 生命周期和平台边界

- 普通前台服务持有唯一引擎并显示运行通知，不使用 VPN / TUN。
- Android 网络地址来自 `ConnectivityManager` / `LinkProperties`，外部 DNS 和 socket 绑定同一选定 Network。
- 回环监听和回环上游不绑定外部网络；不使用进程全局绑网，也不回退到 Android 受限的 netlink 接口。
- 保存配置、请求运行、已加入房间、服务映射就绪是独立状态。修改有效配置由共享核心串行重配。
- 页面展示结构化状态和报告；不收集 Go 原始日志。前台、后台和停止态使用不同的状态刷新策略。

发布检查应覆盖同签名升级、首次启动、主题切换、TCP / UDP 互通、切网恢复和息屏后台运行。
静态 APK 检查与设备运行检查分别记录；桥接约定见 [mobile/README.md](../mobile/README.md)。
