# Hole PenMods 插件

通过房间连接设备并映射 TCP / UDP 服务，适配词典笔 320×170 横屏。
插件使用共享 Go 核心，提供可视化服务配置、线路状态、NAT 检测和打洞过程。

[安装](#安装) · [使用](#使用) · [连接与诊断](#连接与诊断) · [更新核心](#更新核心) · [构建](#构建) · [项目首页](../README.md)

## 安装

将完整插件目录复制到设备：

```text
/userdisk/PenMods/plugins/hole_plugin/
```

重启 `YoudaoDictPen` 后打开插件。升级时保留设备上的 `config.json`，同时更新 `hole-core`、`libhole_plugin.so` 和 QML 资源。

配置保存于插件目录的 `config.json`，包含明文凭据。配置备份时应一并保存该文件。

## 使用

1. 在“设置”填写服务器、信令密码、房间号、房间口令及设备名。
2. 在“服务”切换提供 / 使用并添加映射，与对端使用相同服务 ID；点按卡片展开编辑。
3. 用主页右侧电源按钮启动或停止，在“设备”查看连接、流量和线路详情。

普通连接使用 ICE / QUIC，支持 IPv4 / IPv6。加入房间与服务连通是独立状态，可用服务数以已就绪的映射为准。
信令状态“通过房间设备接收信令”表示通知由组内设备转发，已有数据连接可继续使用。

### 服务与保存

表单可分别编辑协议、地址和端口，支持停用条目并保留内容。配置自动保存；
连接开启时，有效配置会自动应用，未填完整的内容先保存在本机。保存提示区分“正在应用”“已应用”和失败原因。
修改目标、协议或监听地址会更新对应映射；未受影响的应用会话继续运行。

手工编辑配置时，提供服务的 `service` 使用 `tcp://HOST:PORT` 或 `udp://HOST:PORT`，
使用服务的 `expose` 使用 `HOST:PORT`。IPv6 地址加方括号，如 `tcp://[::1]:22` 和 `[::1]:2222`。

### 中继设置

高级设置可填写 Hole 中继设备名，启用或停用 Hole、UDP、TCP、TLS，并长按拖动调整尝试顺序。
“恢复默认顺序”使用默认计划，未列出的类型不会尝试；TURN 关闭后仍可使用 Hole。

插件可连接固定入口和 CLI 中继。固定入口监听及中继服务需由 CLI 配置，插件不提供服务端开关。
从旧版升级时会清理旧连接模式，身份、服务和 TURN 编辑内容保留；使用共享核心 1.1.0 时，参与连接的核心需同步升级。

## 连接与诊断

“设备”页显示实际路径、连接地址、NAT、延迟和线路流量，点按卡片可展开详情和运行诊断。
固定入口通道显示公布入口、监听 / 拨号方及实际地址，失败后只重试固定路径。

QUIC 表格显示合计、上行和下行的丢包率、峰值速率与平均速率；无样本和缺少对端反馈分别标注。
重试、本机丢弃和网络丢包单独统计。映射流量是应用数据，线路流量包含协议开销，详细口径见 [协议说明](../docs/PROTOCOL.md#重连与状态展示)。

### NAT 检测

主页“网络”或设置页“检测网络”打开独立页面，无需加入房间。支持开始、取消、重新检测及查看 STUN 明细。
结果按映射与过滤、端口特征、网络和记录分组；证据不足或过期时显示对应状态，NAT 类型不保证直连结果。
高级设置支持自动 UDP 端口映射及分类 STUN 地址，默认值见 [配置示例](../config.example.yaml)。

### NAT 打洞过程

在设备卡片中点按“打洞过程”，可切换设备、连接尝试、轮次和校准次数：

| 视图 | 操作 |
| --- | --- |
| 阶段 | 展开连接准备、模型交换、校准、探测、握手和通道协商的时间线 |
| 端口 | 查看两端端口计划与矩阵，点按格子筛选对应报文 |
| 报文 | 按 IP、端口、方向、类型或 STUN 事务筛选，查看收发详情 |
| NAT 采样 | 按公网 IP 和 socket 查看端口趋势及对应 STUN 记录 |
| 回放 | 暂停展示、拖动时间轴、逐条前进或后退，点按“回到实时”继续 |

暂停展示不会停止连接。向上滚动后保留阅读位置，手动滑到底部或点按“回到底部”后继续跟随新记录。
核心保留最近 6 次连接尝试，超出记录窗口的数量单独显示；进入中继后仍可查看此前的直连过程。

## 更新核心

只替换 `hole-core` 时，可在插件目录先写入临时文件，再替换：

```bash
chmod 755 hole-core.new
mv -f hole-core.new hole-core
```

随后点击首页“重载核心”。插件结束旧核心并从同一路径启动新文件，原先开启的连接按当前配置重新建立；
现有会话、NAT 检测和统计随旧核心结束。文件缺失或无执行权限时显示错误并保留旧进程，启动失败后可修正并重试。
“运行诊断”的核心版本与构建标识可用于确认更新结果。

## 构建

需要 PenMods 的 ARM64 Qt 和 Zig 交叉工具链。在仓库根目录执行：

```bash
QT=/path/to/qt CROSS=aarch64-linux-gnu.2.27 ./penmods/build.sh
```

脚本构建共享核心和 Release 插件库，并打包 QML 资源。输出为：

```text
dist/penmods/hole_plugin/
├── Main.qml
├── SettingsPage.qml
├── ConfigPage.qml
├── NATPage.qml
├── NATPunchProcessPage.qml
├── components/
├── hole-core
├── hole-core.sha256
├── libhole_plugin.so
├── icon.png
└── metadata.json
```

版本、缓存和构建参数见 [构建指南](../docs/BUILDING.md)，宿主接口见 [stdio 桥接](../desktop/README.md#协议-v1)。
